Paint stickers on the net to set a position: pick a color, then click or drag. Right-click a sticker to pick up its color. Whenever the painted position is valid, it becomes the position.

    Solves the position at the end of the alg with twsearch, natively through the twsearch bridge if it is running on this computer, otherwise in the browser.

      Solving with twsearch
      
          
      
          
      
            
      The Solver hands twsearch the position at the end of the alg, as a
              state, and applies the solution you click.  A search runs either in
              this browser (WebAssembly) or, if the bridge is running on this
              computer, natively, which is much faster.  Export... gives you
              the whole search as one file to run with your own twsearch.
      

            
      Move set
      
            
      Comma separated move names, as this puzzle names them:
              U,R,F, or u,r,f for a different set of
              moves.  No spaces.  Leave it blank for the puzzle's own moves.  The
              move set decides the puzzle twsearch is given, so it also decides
              which positions count as solvable, in the Colors tab as well.  It is
              kept per puzzle while the page is open, and is not part of the URL.
      

            
      Options
      
            
      Anything below can go in the Options field, separated by spaces.
              --checkbeforesolve is always added, so an unsolvable
              position is refused instead of searched for ever.
      
            
      
            
      twsearch's other commands (-g, --schreiersims
              and the rest) are not available here; they do not solve a position, and
              the browser build leaves most of them out.
      

            
      Running twsearch natively
      
            
      Searching in the browser is fine for small puzzles, but a 3x3x3 from
              the Scramble button wants a real twsearch: all your cores, and as much
              memory as you care to give it.  The Explorer will use one running on
              your own computer, through a small program called the bridge, and says
              native (twsearch bridge) in the status while it does.  Nothing
              is uploaded: the bridge listens only on your own machine, and this page
              hands it the same file the Export... button shows you.
      
            
      You need git and a C++ compiler.  Then:
      
            
      
            
      Leave that running and come back to this page; the Solver finds it by
              itself (the channel next to the Solve button says Auto).  The first
              search on a puzzle spends its time building a pruning table, and later
              searches on the same puzzle reuse it, so they are much quicker: a
              3x3x3 took about four minutes and then seconds.  Give it more memory
              for a faster search: -M 16384 is 16GB, and the
              -M a search asks for never exceeds it.

              you gave it, and stops with Ctrl-C.  (There is also a version that runs
              under node, src/js/twsearch-bridge.mjs, which behaves the
